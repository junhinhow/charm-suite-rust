# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

* `Answers` with aggregate validation, pretty JSON serialization, and writer output.
* `validate_field`, `normalize_type`, duplicate-name checks, and regex validation
  during load and answer submission.
* Interactive `renderer::Model`, `renderer::run`, and `run_with_options` using
  `charmed-bubbletea`, plus the `charm-form` CLI (`-file`, `-out`, and
  `-json=false`).
* Go-port tests for validation, answer serialization, CLI summaries, renderer
  keyboard behavior, scripted runs, and cancellation.
* Go-generated parity coverage for form JSON, answers JSON, and validation.

### Changed

* `FormSpec::run` remains the specification-to-JSON helper; interactive answer
  collection is provided by `renderer::run` and the CLI.

## [0.1.0] - 2026-10-22

### Added

* `FormSpec`, `FieldSpec`: the form model, with the same YAML and JSON schema
  as the Go original.
* `load_from_file` and `load_from_bytes`: YAML loading with the same
  validation rules as the Go implementation (`title`, at least one field,
  `name`, `type`, a known type, and options for `select`/`multiselect`).
* `to_json`: pretty-printed JSON with two-space indentation, matching Go's
  `json.MarshalIndent`.
* `run`: prints the form as JSON to standard output.
* Error type `Error` (built with `thiserror`).
* Parity test suite backed by a golden file generated by the original Go
  implementation (`reference/go/charm-form/cmd/parity`).
* Runnable example (`cargo run -p charm-form --example charm_form_demo`).
