# charm-dialog

> [Read in Portuguese](README.pt-br.md)

Modal dialog boxes for terminal user interfaces, styled with
[lipgloss](https://crates.io/crates/lipgloss).

This crate is a Rust port of the Go library
[`github.com/junhinhow/charm-dialog`](https://github.com/junhinhow/charm-dialog)
and reproduces its layout and behaviour. Its rendering is checked against
golden files generated by the Go original.

## Installation

```toml
[dependencies]
charm-dialog = { git = "https://forgejo.multiservidores.com.br/ajr/CharmSuite-Rust", tag = "v0.1.0" }
```

Not yet published on crates.io; install from git.

## Usage

```rust
use charm_dialog::Dialog;

fn main() {
    let mut dialog = Dialog::new_confirm("Confirmar", "Deseja continuar?");

    // Move the selection to "No" and read the chosen label.
    dialog.next_button();
    assert_eq!(dialog.selected_button(), "No");

    // Render the box centered in 60 columns.
    println!("{}", dialog.render(60));

    // Or draw it centered inside a 80x24 area, over an existing screen.
    println!("{}", dialog.render_overlay(80, 24));
}
```

A runnable version lives in `examples/charm_dialog_demo.rs`:

```bash
cargo run -p charm-dialog --example charm_dialog_demo
```

## Dialog types

| Constructor | Buttons | Type |
|-------------|---------|------|
| `Dialog::new_confirm(title, message)` | `Yes`, `No` | `DialogType::Confirm` |
| `Dialog::new_alert(title, message)` | `OK` | `DialogType::Alert` |
| `Dialog::new_input(title, prompt)` | `Submit`, `Cancel` | `DialogType::Input` |
| `Dialog::new_custom(title, message, &buttons)` | the given labels | `DialogType::Custom` |

## API

| Item | Description |
|------|-------------|
| `DialogType` | `Confirm`, `Alert`, `Input`, `Custom` |
| `Styles { title_style, message_style, button_style, active_button_style, border_style }` | Styles used by the box |
| `Styles::default()` | The default palette of the Go `DefaultStyles()` |
| `Dialog { title, message, buttons, selected, r#type, input_value, input_prompt, styles }` | A dialog. All fields are public |
| `Dialog::new_confirm`, `new_alert`, `new_input`, `new_custom` | Constructors |
| `Dialog::with_styles(self, styles)` | Replaces the styles and returns the dialog |
| `Dialog::set_styles(&mut self, styles)` | Replaces the styles in place |
| `Dialog::next_button()` / `prev_button()` | Moves the selection, clamped at the edges |
| `Dialog::selected_button()` | Label of the selected button, or `""` |
| `Dialog::set_key_msg(&KeyMsg)` | Handles a key press; returns `(Action, consumed)` |
| `Dialog::handle_msg(&Message)` | Handles a Bubble Tea message; key messages go to `set_key_msg` |
| `Dialog::render(width)` | The box, centered in `width` columns (`0` = no centering) |
| `Dialog::render_overlay(width, height)` | The box centered in a `width` x `height` area |
| `Action` | `None`, `Submit`, `Cancel`. `Display` prints `none`, `submit` or `cancel` |

## Keyboard

Key handling uses the `KeyMsg` type of `charmed-bubbletea`, the runtime used
by this workspace. Inside an `update` function, pass the message to
`handle_msg`:

```rust
use charm_dialog::{Action, Dialog};
use charmed_bubbletea::{KeyMsg, KeyType};

let mut dialog = Dialog::new_input("Rename", "Enter new name:");
for c in "docs".chars() {
    dialog.set_key_msg(&KeyMsg::from_char(c));
}

let (action, consumed) = dialog.set_key_msg(&KeyMsg::from_type(KeyType::Enter));
assert_eq!(action, Action::Submit);
assert!(consumed);
```

When `consumed` is `false`, the application should keep its normal key
processing.

| Key | Effect |
|-----|--------|
| `left` | Previous button |
| `right`, `tab` | Next button |
| `shift+tab` | Previous button |
| `enter` | `Action::Submit` |
| `esc` | `Action::Cancel` |
| printable characters (input dialogs) | Appended to `input_value` |
| `backspace` (input dialogs) | Deletes the last character |
| `ctrl+u` (input dialogs) | Clears `input_value` |

The text cursor does not move: text is always typed at the end.

## Input dialogs

The text typed so far lives in `input_value`. The box shows the prompt, then
the value followed by an underscore as a cursor:

```rust
use charm_dialog::Dialog;

let mut dialog = Dialog::new_input("Entrada", "Digite seu nome:");
dialog.input_value = "Ana".to_owned();

let text = charm_core::strip_ansi(&dialog.render(0));
assert!(text.contains("Digite seu nome:"));
assert!(text.contains("Ana_"));
```

## Parity with the Go original

The golden file `tests/golden/dialog.txt` is generated by the Go program in
`reference/go/charm-dialog/cmd/parity`. It covers every dialog type, the
navigation, `Render` at widths 0, 40 and 80, and `RenderOverlay` at two
sizes. The comparison removes ANSI codes and trailing spaces on both sides.

```bash
cargo run -p charm-parity --bin parity -- gen \
    crates/charm-dialog/tests/golden/dialog.txt -- \
    go run ./reference/go/charm-dialog/cmd/parity

cargo test -p charm-dialog
```

The width `20` is not in the golden file: it is narrower than the button row,
where the Go output is outside the documented limit. See below.

## Known differences

| Go | Rust |
|----|------|
| `dialog.DefaultStyles()` | `Styles::default()` |
| `WithStyles` (pointer receiver: changes the dialog and returns a copy) | `set_styles(&mut self)` changes the dialog; `with_styles(self)` consumes it and returns the new one |
| `SelectedButton`, `Render`, `RenderOverlay` (value receivers) | `selected_button(&self)`, `render(&self)`, `render_overlay(&self)` |
| `Dialog.Type` | `Dialog.r#type` (`type` is a Rust keyword) |
| `Buttons []string` | `buttons: Vec<String>`; constructors take `&str` |
| `NewCustom(title, message, buttons []string)` | `Dialog::new_custom(title, message, &[&str])` |
| `Selected int` | `selected: usize` |
| `SetKeyMsg(tea.KeyPressMsg)`, `HandleMsg(tea.Msg)` | `set_key_msg(&KeyMsg)`, `handle_msg(&Message)` from `charmed-bubbletea` |
| `Action.String()` | `Display` for `Action`, with the same texts |
| `width` and `height` as `int` (negative values are accepted) | `usize`; a negative value does not compile |

The behaviour is the same: `NextButton` and `PrevButton` stop at the edges
without wrapping, `SelectedButton` returns `""` when there are no buttons, and
`Render(0)` skips the horizontal centering.

**Narrow widths.** When `width` is smaller than the button row, the Go
output can be wider than `width` (for example, 22 columns for `width` 20) and
the buttons wrap in other places. The port keeps every line within `width`,
as the Go documentation describes. The line-wrapping of the button row also
differs by a column or two from the Go output at those widths.
