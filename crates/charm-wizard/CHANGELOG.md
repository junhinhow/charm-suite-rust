# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Synchronized with the Go `charm-wizard` after its state, undo and progress
changes.

### Added

- `Wizard::run_step_to` and `Wizard::progress`, `is_first`, `is_last` and
  `current_step_name`.
- Typed getters `get_string`, `get_bool` and `get_int`, which return `None`
  for a missing key or a value of another type.

### Changed

- `run` starts at the current step, so `go_to` followed by `run` skips the
  earlier steps. Before, it always started at step 0.
- `run` prints each progress block after its step runs, including the block
  of a failed step, and then stops.
- `run_step` prints the progress of the step, as the Go `RunStep` does.
- `back` restores the shared data to the state it had before the step being
  left ran.
- `forward` refuses to move past a step that failed.
- `run` redraws each progress block in place when standard output is a
  terminal. `run_to` never does.
- Progress texts match Go: `Etapa N de M: <description>` and
  `✓ <title> concluído com sucesso!`. Before, they were in English.
- The parity golden file is regenerated from the new Go program.

## [0.1.0] - 2026-10-22

### Added

- `Wizard` with `new`, `with_title`, `add_step`, `set_data`, `data`,
  `current_step`, `total_steps`, `steps`, `back`, `forward`, `go_to`, `run`,
  `run_step`, ported from the Go `wizard.Wizard`.
- `Wizard::run_to`, which writes the run output to any `std::io::Write`
  (`run` writes to standard output).
- `Step` with `name`, `description` and `run_func`; steps are closures
  `FnMut(&mut DataMap) -> Result<(), Error>`.
- `DataMap` (`HashMap<String, serde_json::Value>`) shared by all steps.
- `render_progress`: dots (`[*]` done, `[>]` current, `[ ]` pending), a 30-cell
  bar with percentage and the step description, styled with `lipgloss`.
- `Error` with `NoSteps`, `InvalidIndex`, `StepFailed` (keeps the original
  error as its source), `Custom` and `Io`.
- Golden file `tests/golden/wizard.txt` generated by the Go implementation,
  verified by `tests/parity.rs`.

### Known differences

- `Wizard::go_to` takes a `usize`, so Go's negative indices cannot be passed.
  Any out-of-range value returns `Error::InvalidIndex`.
- `render_progress` returns an empty string for an out-of-range index, where
  the Go implementation panics.
- Steps return `charm_wizard::Error`; use `Error::custom` for messages.
- Error messages are in English.
- The output always contains ANSI escape sequences, while the Go implementation
  only emits colours when stdout is a TTY.
