# charm-banner

ASCII art banner generator for terminal UIs — styled with [Lip Gloss](https://github.com/charmbracelet/lipgloss).

> [Leia em Português](README.pt-br.md)

This crate is a Rust port of the Go library
[`charm-banner`](https://github.com/junhinhow/charm-banner) and keeps its
behavior **byte-for-byte compatible**, including the bitmap font data, which
was extracted programmatically from the original Go source.

## Features

- Convert text to large ASCII art using Unicode block elements (`▀▄█░▒▓`)
- Three built-in font sizes: **Small** (3 rows), **Medium** (5 rows) and **Large** (7 rows)
- Full [Lip Gloss](https://github.com/charmbracelet/lipgloss) styling support
- Supports letters A–Z, digits 0–9 and common punctuation (`!`, `.`, `-`, `:`)
- Characters without a glyph fall back to the space glyph, exactly like the Go original

## Install

```toml
[dependencies]
charm-banner = "0.1"
```

## Usage

```rust
use charm_banner::{render, Font, RenderOption};
use lipgloss::{Color, Style};

fn main() {
    // Simple banner (the Medium font is the default).
    println!("{}", render("HELLO", &[]));

    // With another font size.
    println!("{}", render("GO", &[RenderOption::Font(Font::Large)]));

    // With Lip Gloss styling.
    let style = Style::new().bold(true).foreground(Color("#ff79c6".to_owned()));
    println!("{}", render("CHARM", &[RenderOption::Style(style)]));
}
```

Run the bundled demo:

```bash
cargo run -p charm-banner --example demo
```

## API

The canonical API is a free function that takes a slice of options:

| Item | Description |
|------|-------------|
| `render(text: &str, opts: &[RenderOption]) -> String` | Renders text as an ASCII art banner |
| `RenderOption::Font(Font)` | Selects the font size: `Small`, `Medium`, `Large` |
| `RenderOption::Style(lipgloss::Style)` | Applies a Lip Gloss style to the output |
| `render_with(text: &str, opts: &RenderOptions) -> String` | Same as `render`, with builder-style options |
| `RenderOptions::new()` / `::with_font(..)` / `::with_style(..)` | Builder-style options |
| `Font::height()` / `Font::width()` / `Font::name()` / `Font::glyphs()` | Font metadata and glyph map |
| `CharPattern { rows }` | The bitmap pattern of a single character |
| `SMALL_FONT` / `MEDIUM_FONT` / `LARGE_FONT` | The glyph maps of the three fonts |

Two equivalent ways to render a banner:

```rust
use charm_banner::{render, render_with, Font, RenderOption, RenderOptions};

// 1. Canonical: a slice of options.
let a = render("HI", &[RenderOption::Font(Font::Small)]);

// 2. Builder: the same result, with a named options struct.
let b = render_with("HI", &RenderOptions::new().with_font(Font::Small));

assert_eq!(a, b);
```

Options are applied in order, so the last one wins — exactly like the variadic
`Option` list of the Go original.

## Fonts

| Font | Rows | Nominal columns | Glyphs |
|------|------|-----------------|--------|
| `Font::Small` | 3 | 3 | 41 |
| `Font::Medium` | 5 | 5 | 41 |
| `Font::Large` | 7 | 7 | 41 |

Each font contains the glyphs of `A`–`Z`, `0`–`9`, the space and the
punctuation `!`, `.`, `-` and `:`. Every other character is rendered with the
space glyph.

The font data lives in `src/fonts.rs`, which is **generated** by
`xtask/extract_fonts.rs` directly from `reference/go/charm-banner/banner.go`:

```bash
rustc --edition 2021 crates/charm-banner/xtask/extract_fonts.rs -o extract_fonts
./extract_fonts reference/go/charm-banner/banner.go crates/charm-banner/src/fonts.rs
```

## Parity with the Go implementation

The parity harness compares the Rust output with the Go original byte-for-byte.
The golden file `tests/golden/banner.txt` is generated by the Go program
`reference/go/charm-banner/cmd/parity`, which dumps every glyph of the three
fonts and a set of rendered banners:

```bash
cargo run -p charm-parity --bin charm-parity -- gen \
    crates/charm-banner/tests/golden/banner.txt -- \
    go run ./reference/go/charm-banner/cmd/parity

cargo test -p charm-banner
```

The comparison strips the ANSI codes (the Rust port always emits them, the Go
one only does so on a TTY) and keeps the trailing blanks of every line, so the
spacing of the original glyphs is verified as well.

## Known differences

These are quirks of the Go original that the port reproduces on purpose:

- **Ragged glyph rows.** `fontWidth` advertises 3, 5 and 7 columns, but the
  glyphs of the Go fonts are in fact 3, 6 and 9 columns wide. The function is
  never used while rendering, so the port keeps the original data untouched.
- **Blank column after multi-byte characters.** The Go code compares the *byte*
  offset of a rune with the *byte* length of the string, so a blank column is
  also appended after a character that uses more than one byte (for example
  `É`). The port reproduces this byte-for-byte.
- **Upper-casing.** Go uses the *simple* Unicode uppercase mapping (`ß` stays
  `ß`); Rust's `str::to_uppercase` uses the *full* mapping (`ß` becomes `SS`).
  The port implements the simple mapping so that the number of rendered glyphs
  does not change.
