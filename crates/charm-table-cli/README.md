# charm-table-cli

> [Leia em portugues](README.pt-br.md)

A command-line tool that renders CSV, TSV, JSON and JSON Lines as styled
tables in the terminal, using [lipgloss](https://crates.io/crates/lipgloss)
for styling.

This crate is a Rust port of the Go command
[`github.com/junhinhow/charm-table-cli`](https://github.com/junhinhow/charm-table-cli).
The crate is named `charm-table-cli`, but the binary it installs is called
**`charm-table`**.

## Installation

```bash
cargo install --git https://forgejo.multiservidores.com.br/ajr/CharmSuite-Rust charm-table-cli
```

Not yet published on crates.io; install from git.

## Usage

```bash
# From a file
charm-table data.csv

# From a pipe
cat data.csv | charm-table

# Other styles and options
charm-table --style thick --color "#ff0000" data.csv
charm-table --no-header --max-width 60 data.csv
```

The input format is detected automatically:

| Input starts with | Format |
|---|---|
| `[` | JSON array of objects. The keys of the first object become the columns. |
| `{` | JSON Lines: one object per line. |
| anything else | Delimited text. Tab-separated when the first line contains a tab, comma-separated otherwise. |

For delimited text, the first row is the header by default. With `--no-header`,
columns are named `Col1`, `Col2`, and so on.

## Flags

| Flag | Type | Default | Description |
|---|---|---|---|
| `--style <STYLE>` | `rounded`, `thick`, `double`, `ascii` | `rounded` | Border style. |
| `--header` / `--no-header` | switch | `--header` | Uses the first row as the header, or generates `Col1`, `Col2`, ... |
| `--max-width <N>` | integer | `0` | Shrinks the columns to fit about `N` characters. `0` means no limit. |
| `--color <COLOR>` | ANSI index or hex | `63` | Header color: an ANSI 256 index (`63`) or hex (`#ff0000`). |
| `[FILE]` | path | stdin | Input file. Without it, the input is read from stdin. |
| `-h`, `--help` | | | Prints help. |
| `-V`, `--version` | | | Prints the version. |

### Border styles

| `--style` | Characters | Example corners |
|---|---|---|
| `rounded` | `─│╭╮╰╯` | `╭ ╮ ╰ ╯` |
| `thick` | `━┃┏┓┗┛` | `┏ ┓ ┗ ┛` |
| `double` | `═║╔╗╚╝` | `╔ ╗ ╚ ╝` |
| `ascii` | `─│┌┐└┘` | `┌ ┐ └ ┘` |

`ascii` draws single lines, as in the Go original. It does not use `+`, `-`
and `|`.

## Example

Input (`people.csv`):

```csv
nome,idade,cidade
Ana,31,Recife
Bruno,27,Salvador
```

Command and output (ANSI codes removed):

```text
$ charm-table people.csv
╭───────┬───────┬──────────╮
│ nome  │ idade │ cidade   │
├───────┼───────┼──────────┤
│ Ana   │ 31    │ Recife   │
│ Bruno │ 27    │ Salvador │
╰───────┴───────┴──────────╯
```

This is the real output of the tool, and it matches the Go original. Each
column is as wide as its longest value, plus one space of padding on each side,
so every row stays on one line and the borders line up.

Run the demo to see every border style:

```bash
cargo run -p charm-table-cli --example charm_table_cli_demo
```

## Parity with the Go original

The output is checked against a golden file generated by the Go program
(`reference/go/charm-table-cli/cmd/parity`). The golden file covers CSV, TSV,
JSON array and JSON Lines input, every border style, `--no-header`,
`--max-width` and `--color`.

```bash
cargo run -p charm-parity --bin parity -- gen \
    crates/charm-table-cli/tests/golden/table.txt -- \
    go run ./reference/go/charm-table-cli/cmd/parity

cargo test -p charm-table-cli
```

## Known differences

| Go | Rust | Notes |
|---|---|---|
| `charm-table-cli` binary | `charm-table` binary | The crate has a different name from the binary. |
| `-style thick`, `-header=false` (single dash) | `--style thick`, `--no-header` | The Rust CLI uses clap, which accepts double dashes only. |
| `-style nope` falls back to `rounded` | Error, exit code 2 | Invalid values are rejected instead of silently replaced. |
| Columns of a JSON object are in random order (Go map iteration) | Columns follow the document order of the first record | Random order cannot be reproduced. |
| TSV with an empty cell in the middle (`1\t\t3`) fails with `wrong number of fields` | Parsed as three fields | In Go, `TrimLeadingSpace` also skips tab delimiters, so the empty field disappears. |
| Error text from the CSV reader: `record on line 4: wrong number of fields` | `record N (line: L, byte: B): found record with X fields, ...` | Error prefixes match; the detail comes from the `csv` crate. |
| Indexed ANSI colors (`38;5;63`) | Truecolor sequences (`38;2;95;95;255`) | `lipgloss` converts indexed colors to RGB. The color shown is the same. |
| `bufio.Scanner` stops at 64 KB lines in JSON Lines | No line limit | The Go behavior is a limit of the scanner, not a feature. |
| Invalid UTF-8 is passed through | Replaced with U+FFFD | Rust strings must be valid UTF-8. |

### Inherited from the Go original

These behaviors are reproduced on purpose, to keep parity:

- **`--max-width` is approximate.** Each column loses the same share of the
  excess and never goes below 3 characters, so a very narrow table can still
  be wider than the limit.
- **Lengths are counted in characters (Unicode scalar values, Go runes).** They
  are not terminal display columns, so wide characters such as CJK or emoji
  can misalign the table. This is the same as Go.
- **`--max-width` truncation** ends a cell with `...` when at least 4 characters
  fit, and cuts the text without an ellipsis otherwise.
- **Numbers** use Go's `%g` formatting: `1e-07`, `1.23456785e+07`. Integers that
  fit in 64 bits print without a decimal point. Nested arrays and objects are
  encoded as compact JSON with sorted keys and `<`, `>`, `&` escaped as
  `\u003c`, `\u003e`, `\u0026`.
