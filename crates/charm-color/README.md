# charm-color

Color manipulation utilities for terminal UIs — darken, lighten, blend,
contrast, complementary colors and harmonious palettes.

> **[Leia em Português](README.pt-br.md)**

This crate is a Rust port of the Go library
[`charm-color`](https://github.com/junhinhow/charm-color). Every function
reproduces the original implementation bit-for-bit, including its truncation
and rounding rules.

## Install

```toml
[dependencies]
charm-color = { git = "https://forgejo.multiservidores.com.br/ajr/CharmSuite-Rust", tag = "v0.1.0" }
```

Not yet published on crates.io; install from git.

## Usage

```rust
use charm_color::{blend, complementary, contrast, darken, lighten, palette};
use charm_core::Rgb;

fn main() {
    let red = Rgb::rgb(255, 0, 0);

    println!("dark:        {}", darken(red, 0.3).to_hex());
    println!("light:       {}", lighten(red, 0.3).to_hex());
    println!("complement:  {}", complementary(red).to_hex());
    println!("text color:  {}", contrast(red).to_hex());
    println!("blend:       {}", blend(red, Rgb::white(), 0.25).to_hex());

    for (index, color) in palette(red, 5).iter().enumerate() {
        println!("  palette[{index}]: {}", color.to_hex());
    }
}
```

A runnable version of this example lives in `examples/demo.rs`:

```bash
cargo run -p charm-color --example demo
```

## API

| Function | Description |
|----------|-------------|
| `darken(color, amount)` | Darkens a color by a factor (0.0-1.0) |
| `lighten(color, amount)` | Lightens a color by a factor (0.0-1.0) |
| `blend(c1, c2, t)` | Interpolates between two colors |
| `contrast(color)` | Returns black or white for text readability |
| `complementary(color)` | Returns the complementary (opposite) color |
| `palette(base, n)` | Generates `n` harmonious colors by hue rotation |
| `from_lipgloss(&str)` | Parses a lipgloss color string (`"#rrggbb"`, ANSI-256) |

`Rgb::to_hex`, `Rgb::from_hex` and `Rgb::from_hex_or_black` come from the
[`charm-core`](https://forgejo.multiservidores.com.br/ajr/CharmSuite-Rust/src/branch/main/crates/charm-core) crate and are re-exported
through the [`Rgb`] type.

## Parity with the Go original

The crate ships a golden file (`tests/golden/color_ops.txt`) generated by the
original Go implementation, and a test that compares both outputs
byte-for-byte:

```bash
# regenerate the golden file from the Go reference
cargo run -p charm-parity --bin parity -- \
    gen crates/charm-color/tests/golden/color_ops.txt -- \
    go run -C reference/go/charm-color ./cmd/parity

# run the parity test
cargo test -p charm-color --test parity
```

## Known differences

The port reproduces the Go behavior, including a few quirks that are worth
being explicit about:

- **Premultiplied alpha.** The Go implementation reads colors through
  `color.NRGBA.RGBA()`, which premultiplies the RGB channels by the alpha
  channel. This port does the same, so operations on translucent colors
  operate on premultiplied values.
- **Truncation, not rounding.** `darken`, `lighten` and `blend` truncate the
  resulting channels (`255 * 0.5` becomes `127`, not `128`), while the HSL
  to RGB conversion of `palette` rounds them. Both rules are preserved.
- **`from_lipgloss` and out-of-range indexes.** The Go original passes the
  string to `lipgloss.Color`, which interprets values above `255` as a packed
  24-bit RGB value and negative values as their absolute value. This port
  delegates to `charm_core::Rgb::from_lipgloss_str`, which resolves indexes
  `0..=255` and falls back to black for anything else.
- **`from_hex` is strict.** The Go original parses the hex string with
  `fmt.Sscanf`, which accepts some unusual inputs (for example `"12 456"`).
  `charm_core::Rgb::from_hex_or_black` accepts only `#rrggbb` and `rrggbb`
  and returns opaque black for anything else, like the Go original does for
  malformed strings.
